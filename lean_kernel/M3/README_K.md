# 45a M3: the T(c) bound from a certified prime list (K version, kernel-only)

New files on top of the N version (`M3/README_M3.md`).
Toolchain v4.35.0-rc3, Mathlib c55e6e786f49.

## Statement
```lean
theorem Romanoff.M3.tboundLitK (h5 : R0Bound) : TBound R45.M3.teffLit
```
Same `teffLit` (`RCert/M3/TeffLit.lean`) as the N version, so it replaces `tboundLit` unchanged.
`#print axioms Romanoff.M3.tboundLitK`: propext, Classical.choice, Quot.sound (no native_decide).

## How it is proved
`tbound_of D.data certOK sumsOK h5` (N v2, standard axioms) with every computed quantity checked by the kernel:
* `RCert/M3/KFun.lean`: the checker's computations written with `Nat.rec`/`List.rec` directly and Boolean tests
  (`Nat.blt`, `Nat.ble`, `Nat.beq`, `cond`), `noncomputable`; the kernel reduces these 3-6x faster than the
  structural-recursion definitions. Tables are packed literals (64 entries of 154 bits per natural number, `decTabK`).
* `Romanoff/M3/KEq.lean`: these functions equal the checker functions (`mergeK_eq`, `sortK_eq`, `runDPDK_eq`, `sumRK_eq`,
  ...); `segOK_sound`, `segROK_sound` turn a DP segment check into `runDPD`/`runDP` equations.
* `Romanoff/M3/KSplit.lean`: `accG s tab` from the 16 subtables `gcd(L, 120) = h` (bucket sums `bsum`, partition
  `bsum_split`, one scalar pass per subtable with a per-entry check that `gcd(lcm(L, s), 120)` is the bucket,
  `accSplitK_sound`), `mkBDS_sound`, `bdChunkOK_sound`, `teffOf_eq_V`.
* `Romanoff/M3/KGlue.lean`: chaining lemmas (`seg_step`, `segR_step`, `map_seg`, `drop_drop'`).
* `Romanoff/M3/K/` (generated by `M3/tools/gen_kfiles.py` from `M3/data/pratt_v1.json` and
  `M3/data/kplan.json` (`M3/tools/gen_kplan.py`)): literal modules `Tab<k>` (DP after k groups of gA, with the dropped
  mass `drop<k>`), `TabR1..8`, `TabR` (R0 table after each group of gE), `Sub<h>`, `Vals`, `BDs`; and 244 kernel
  shards, one `decide +kernel` theorem each: `KDP1..43` (DP segments), `KR1..9` (R0 table), `KSub<h>`, `KVsA`, `KVsB`,
  `KVr0a`, `KVacc1` (pass values), `KB0..114` (class-B data in chunks), `KF` (the final evaluation `teffOfV = teffLit`
  and `sumA ≤ ∏`), `KCr0..50`, `KCs`, `KCb`, `KCg`, `KCp`, `KCm` (`certOK`, split).
* `Romanoff/M3/KMain.lean` (generated by `M3/tools/gen_kglue.py` from `Romanoff/M3/K/plan.json`): the glue.

## Build
1. `lake build RCert.M3.Data RCert.M3.KFun Romanoff.M3.KGlue RCert.M3.TeffLit` and the literal modules:
   `lake build $(ls Romanoff/M3/K | grep -E '^(Tab|Sub|Vals|BDs)' | sed 's/.lean$//; s/^/Romanoff.M3.K./')`.
2. The shards: `python3 M3/tools/kbuild45.py Romanoff/M3/K/jobs.txt MEMCAP_GB MAXJOBS` from the project root
   (memory-aware: 2 GB + 0.2 GB per estimated kernel second per job; results in `M3/logs/kbuild45.tsv`). Measured on 22
   cores: 4.7 CPU-h kernel, about 45 min wall with MEMCAP 150; per shard typically 12-15 GB, at most about 20 GB (KF, KDP1).
   (`lake build Romanoff.M3.KMain` also works, given about 15 GB per parallel job.)
3. `lake env lean -o .lake/build/lib/lean/Romanoff/M3/KMain.olean -i .lake/build/lib/lean/Romanoff/M3/KMain.ilean
   Romanoff/M3/KMain.lean` (20 s), then `#print axioms Romanoff.M3.tboundLitK`.

## Reproducing the generated files
`python3 M3/tools/gen_kplan.py M3/data/pratt_v1.json PLAN.json 250000` gives `M3/data/kplan.json`;
`python3 M3/tools/gen_kfiles.py M3/data/pratt_v1.json M3/data/kplan.json OUTDIR 6` regenerates `Romanoff/M3/K/`
byte for byte (KAPPA 16384 is the default of `m3ref.py`'s weight pruning in these scripts);
`python3 M3/tools/gen_kglue.py Romanoff/M3/K/plan.json Romanoff/M3/KMain.lean` regenerates the glue.
